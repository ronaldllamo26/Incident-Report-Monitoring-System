I. Project Profile

1. Project Title

Design and Development of a Secure Integrated Incident Report & Monitoring System (QC-ALERTO)

The project title is a specific and descriptive nomenclature that encapsulates the three primary pillars of the study: security, integration, and monitoring. By incorporating "QC-ALERTO," the title identifies its target jurisdiction—Quezon City—and its primary mission of providing an alert-based response mechanism. The term "Secure Integrated" highlights the system's reliance on the "Iron Dome" application-level firewall and a unified data architecture that seamlessly bridges the gap between public reporting and government intervention.

2. Integrated System

The QC-ALERTO IRMS is a multi-tiered platform that integrates three traditionally siloed processes: Citizen Emergency Reporting, AI-Assisted Dispatch, and Administrative Performance Analytics. In current manual setups, these processes exist in isolation, leading to information leakage and delayed response times. This study integrates these systems by creating a shared data backbone where every incident reported by a citizen is instantly analyzed by an Artificial Intelligence engine to determine category and severity. This integration is vital because it ensures that critical metadata, including high-precision GPS coordinates and multimedia evidence, is delivered to the assigned responder within seconds of the report submission. This synergy directly improves operational efficiency and reduces the cognitive load on human dispatchers.

3. Sub-Systems
  • Citizen Reporting Sub-System: A high-performance, mobile-responsive interface designed for public use. It facilitates the capture of incident details, precise geolocation pinning via Leaflet.js, and multi-file evidence uploads. It also provides a feedback loop where citizens can rate responder performance post-resolution.
  • AI Dispatch Sub-System: The intelligence core of the IRMS. It utilizes the Groq Cloud API (Llama-3 model) to process natural language descriptions. Its role is to automatically triage incidents, generate formal disclosures, and suggest severity levels based on real-time textual analysis.
  • Administrative Monitoring Sub-System: A comprehensive dashboard for city officials. It provides visual analytics through Chart.js, real-time incident mapping, and full lifecycle management of every reported emergency, ensuring that no incident goes unaddressed.
  • Iron Dome Security Sub-System: The defensive layer of the IRMS. It enforces global rate-limiting, honeypot traps for bot detection, and mandatory Two-Factor Authentication (2FA) for staff. It ensures the integrity of the database against malicious spam and unauthorized access.

III. Introduction

1. Background of the Study

Quezon City, as the largest and most populous city in the Philippines, faces an immense volume of public safety incidents daily. From localized fires to infrastructure damages, the city's ability to respond is the primary metric of its governance. However, the current "Status Quo" relies heavily on decentralized communication channels—telephone hotlines, radio transmissions, and unverified social media reports. This fragmentation leads to the "Data Fog" phenomenon, where information is often inaccurate, delayed, or lost before it reaches the appropriate responding unit. The lack of a centralized, digital repository prevents the city from performing long-term trend analysis and performance auditing. This study proposes QC-ALERTO to modernize this landscape, providing a singular, secure, and intelligent platform for all stakeholders.

2. Statement of the Problem

The researchers have identified the following critical deficiencies in the existing incident management workflow:

  1. Manual Data Redundancy: Emergency logs are often recorded multiple times in physical books, leading to data inconsistency and difficulty in retrieval for audit purposes.
  2. Unverified Reporting (Spam): Public reporting channels are frequently overwhelmed by non-critical or malicious reports, hindering the dispatch of help to genuine emergencies.
  3. Inaccurate Geolocation: Voice-based reporting often results in responders going to the wrong street or barangay due to miscommunication or lack of landmarks.
  4. Absence of Real-time Accountability: There is no digital mechanism to track the exact timestamp a responder acknowledged and resolved an incident, making performance monitoring impossible.
3. Project Objectives

General Objective: To design and develop a secure, integrated, and AI-powered Incident Report & Monitoring System for Quezon City to streamline emergency workflows and enhance data-driven decision-making.

Specific Objectives:

  • Implement a geofenced reporting module that restricts submissions within Quezon City's administrative boundaries.
  • Develop an AI triage module that can classify incidents and assess severity with at least 90% accuracy.
  • Enforce the "Iron Dome" security layer to prevent automated form spam and SQL injection.
  • Provide a real-time analytics dashboard for monitoring Mean Time to Acknowledge (MTTA) and Citizen Satisfaction (CSAT) scores.

VI. System Design

1. Secure System Architecture

The system follows a Modular Monolith Architecture, which balances the simplicity of deployment with the benefits of modular design. All core logic is housed in a single application container but partitioned into logical modules (e.g., Auth, Incident, AI, Analytics). This design is inherently secure as it allows for a unified security middleware (Iron Dome) that intercepts all incoming HTTP requests to validate CSRF tokens, session integrity, and IP-based rate limits before any business logic is executed.

2. Database and Data Security Design

The database is designed with normalized tables to ensure data consistency. To protect sensitive information, all user passwords are hashed using **Bcrypt** with a high cost factor. The database also implements strict **Foreign Key Constraints** to prevent orphaned records. For data durability, the system includes a "One-Click Backup" module that generates a full SQL dump, ensuring that the system can be restored within minutes in the event of a server failure.

3. Access Control Design

We utilize **Role-Based Access Control (RBAC)**. The system defines three primary roles:

  • Admin: Full system control, user management, and global analytics.
  • Responder: Limited to managing assigned incidents and uploading resolution proof.
  • Citizen: Limited to submitting reports and tracking their own submissions.

VII. System Modules & Features

1. AI-Driven Triage Module

This module acts as the "Virtual Dispatcher." It captures the citizen's natural language description and sends it to the Groq AI engine. The result is a categorized incident (e.g., Fire, Road Accident) and an AI-generated summary. This reduces the time spent by administrators reading lengthy descriptions and ensures that urgent cases are highlighted immediately based on AI-detected keywords.

2. Iron Dome Security Module

This is the system's defensive perimeter. It monitors every IP address interacting with the platform. If a user or bot submits more than 3 reports in an hour, they are automatically rate-limited. It also includes "Honeypot" technology—hidden form fields that bots fill out but humans ignore—to instantly identify and ban automated attackers.

3. Precision Mapping Module

Utilizing Leaflet.js and a customized GeoJSON mask of Quezon City, this module ensures that every report has an accurate geospatial coordinate. It prevents reports from being submitted outside the city's jurisdiction, protecting responders from being dispatched to out-of-scope locations.
